15. CORTEX LIVE CONVERSATION MODE

Current behavior:

User presses mic.
Speaks.
Cortex responds.
Conversation ends.
Context is lost.

This must be redesigned.

Cortex should behave like Gemini Live or ChatGPT Voice.

Requirements:

• Maintain conversation context across consecutive voice interactions.

• Manual Push-to-Talk must NOT reset the conversation.

Example:

User:
"What's the Honda NX200?"

Cortex:
"The Honda NX200 is essentially a rebranded CB200X..."

User presses the microphone again.

User:
"So what's different from my CB200X?"

Cortex must understand:

"my CB200X" refers to the previous discussion.

DO NOT start a new conversation.

────────────────────────────

LIVE MODE

After Cortex finishes speaking:

• Automatically return to listening mode.

• Show a subtle "Listening..." animation.

• No need to press the microphone again.

Conversation continues naturally.

Timeout after configurable inactivity.

────────────────────────────

MANUAL MODE

If Live Mode is disabled:

Push-to-talk should still preserve conversation history.

Each press simply continues the same session.

Never clear context unless:

• User taps New Conversation.
• User explicitly says:
  - Start over.
  - New chat.
  - Forget this conversation.
• Conversation timeout expires.
• User closes Cortex (configurable).

────────────────────────────

SESSION MEMORY

Maintain:

• Previous user messages.
• Previous assistant responses.
• Tool outputs.
• Search results.
• Generated images.
• Current topic.

Only summarize older messages when context becomes too large.

Never discard recent context unnecessarily.
